# Mavuus design system

Tokens, primitives, patterns and organisms for the whole product. Design: `mavuus-app/plans/2026-11-06-design-system-design.md`.

## Conventions

- **Folder per component:** `primitives/Button/{Button.jsx, Button.test.jsx, Button.stories.jsx, index.js}`. Each tier has a barrel (`primitives/index.js`, `patterns/index.js`) with a test that fails when a folder export is missing from it; add every new component to it. Patterns compose primitives and never import organisms (the patterns barrel test checks this). Hooks live in `hooks/` (`useReducedMotion`, `useInView`, `useMediaQuery`).
- **Variants** use `cva` from `class-variance-authority`. Every component with a `cva` call exports it as `xVariants` from its own `xVariants.js` (so the component file only exports components, for react-refresh lint), and the barrel exports it too. Defaults live in `defaultVariants` only; when a lookup map needs the default, take it from the same constant.
- **`variant` vs `tone`:** `variant` is visual emphasis (primary, outline, ghost). `tone` is status meaning (success, warning, error, info) and is used by status components like Badge.
- **Class merging** goes through `cn()` from `lib/cn.js`. It's `twMerge(clsx(inputs))` with our theme keys registered, so `cn('p-ds-md', 'p-ds-lg')` keeps `p-ds-lg` and `cn('text-body', 'text-text-primary')` keeps both.
- **Refs:** `ref` is a normal prop (React 19). No `forwardRef`.
- **Props:** take `className` (merged last with `cn`) and spread the remaining props onto the root element.
- **Interactive parts** with focus, keyboard or layering logic (menus, dialogs, popovers, tooltips) use Base UI (`@base-ui/react`).
- **Stories:** Storybook 10 CSF3, `export default { title: 'Primitives/Button', component: Button, tags: ['autodocs'] }`, one named export per variant or state. Run it with `npm run storybook` (port 6006) or `npm run build-storybook`. Every story renders inside a `MemoryRouter` at `/`; set `parameters: { router: { initialEntries: ['/jobs/42'], path: '/jobs/:id' } }` to start at a URL and render under a route (so `useParams` works). Stories get `p-ds-lg` padding unless `layout: 'fullscreen'`; the background comes from the backgrounds toolbar (page by default), and the theme toolbar sets `data-theme` on `<html>` (dark is a placeholder that falls back to light until it has role tokens). Don't add your own router. Opt-in decorators live in `.storybook/decorators.jsx`: `withToaster` mounts the Toaster (Toast stories use it) and `withAuth(user)` provides the app's AuthContext with a mock value and no network calls (`withAuth()` signs in a demo user, `withAuth(null)` is signed out). Story files end in `.stories.jsx`; `npm run check:stories` fails when a component folder (each folder in `primitives/` and `patterns/`, each component folder in `organisms/<domain>/`) has none.
- **Tests:** test behavior that matters (roles, aria, callbacks, keyboard). Name them "should ... when ...". `test/browserMocks.js` has `mockIntersectionObserver()`, `mockReducedMotion(reduced)`, `mockResizeObserver(size)`, `mockOverflow(widths)` and `mockViewport(width)` for the APIs jsdom lacks; undo them with `vi.unstubAllGlobals()` (and `vi.restoreAllMocks()` after `mockOverflow`).
- **Focus:** the global navy `:focus-visible` outline in `index.css` handles visible focus. Don't add `outline-none`.
- **Sizes:** controls share one height scale in `lib/controlSizes.js`: xs 32px, sm 40px, md 48px, lg 56px (squares use the same steps). md is the default and meets the 44px touch target. sm is for dense desktop toolbars only. Chips are small filter controls and use xs and sm. Every control resolves its `size` with `resolveControlSize(size, allowed, fallback, component)`: a missing size gives the fallback, a size on the scale the component doesn't support gives the nearest allowed step (IconButton and Button `xs` give `sm`, Chip `md` gives `sm`), and any other value gives the fallback. The last two log a dev-only warning naming the component and the size. Don't resolve sizes any other way.
- **Icons:** `leadingIcon` and `trailingIcon` take a lucide component (not an element) on Button, Badge, Chip and Input. The component renders it `aria-hidden` at the size that matches the control. IconButton takes `icon`. A loading Button renders `<Spinner announce={false} />` in place of `leadingIcon` (sr-only "Loading" in its name, no second status) and keeps its resting styles on hover (`aria-disabled:hover:` in `buttonVariantStyles`).
- **Links:** anything that renders `to`/`href` goes through `lib/linkProps.js`. It picks the router Link or an anchor, opens absolute http(s) links in a new tab with `rel="noopener noreferrer"`, and makes disabled or loading links `aria-disabled` and unfocusable. Render `<ExternalHint />` inside the link when it returns `opensNewTab`.
- **Fields:** Input and Textarea share `fieldVariants` and `isInvalid` from `lib/field.js`. Input's `className` and props go to the `<input>`; `wrapperClassName` only applies when an icon or `trailing` slot renders the wrapper.
- **Refs:** combine refs with `lib/mergeRefs.js`, which supports React 19 ref cleanups.
- **Choice controls:** Checkbox, Radio and Switch take `label` and wrap the control and text in a `<label>`, so the text toggles it and the row is at least 44px tall (`lib/choice.js`). Without `label`, pass `aria-label`; the hit area still grows to 44px. `ref` and props go to the control, `className` to the outer element. Checkbox, RadioGroup and Switch take `invalid` (through `isInvalid`), and RadioGroup takes `label` (visible, wired with aria-labelledby) and `required`. Required labels (Label, RadioGroup) render `lib/RequiredMark.jsx`: an aria-hidden asterisk plus sr-only "(required)".
- **Base UI parts:** style them with their data attributes (`data-[checked]:`, `data-[highlighted]:`, `data-[disabled]:`, `data-[popup-open]:`, `data-[starting-style]:`). Layered popups use the z-index aliases through `z-(--ds-z-dropdown)` and `z-(--ds-z-tooltip)`.
- **Tooltips:** the content is always mounted in a hidden element, portaled to `document.body` so the trigger gets no extra siblings, that the trigger references with `aria-describedby` (merged with any existing one), and the visual popup is `aria-hidden`, so the hint is announced once. The trigger still needs its own accessible name; Tooltip warns in dev when it has none. Style the popup with `popupClassName`; other props go to the trigger.
- **Standalone icons** (Icon, Spinner) use `lib/iconSizes.js`: sm 16px, md 20px, lg 24px. Patterns render lucide icons through the Icon primitive.
- **Typography tones** mean the same thing on Heading, Text, Eyebrow and Caption: primary, secondary, muted, brand (`text-text-brand-strong`, readable), link, on-brand, success, warning, error, info. Eyebrow adds `accent` (`text-text-brand`, the light pink, 2.85:1 on white) and uses it by default; it is decorative only, so the heading below must carry the meaning. Unknown tones, sizes and levels warn in dev and fall back (`lib/resolveOption.js`); Heading levels 5 and 6 render an h4.
- **Motion:** every animation or transition that moves things gets `motion-reduce:` handling. Scroll reveals use `patterns/Reveal` (the `[data-reveal]` rules, the capped `[data-reveal-step]` stagger, `.ds-float` (with `.live-float` as an alias until the public site migrates) and `.ds-animate-fade-in` live in `styles/motion.css`, imported once from `src/index.css`). JS that depends on the preference reads `useReducedMotion()` from `hooks/`; `useInView(ref)` reports when an element has scrolled into view.
- **Styling:** only token classes. No hex values, no arbitrary px values. Tailwind numeric sizes (`h-12`, `size-4`) are fine for fixed control heights and icon sizes.

- **Heading levels:** every pattern that renders a title heading takes `headingLevel` (SectionHeader, EmptyState, Accordion), resolved with `resolveHeadingLevel` from `lib/resolveOption.js` (unsupported levels warn in dev and fall back). PageHeader is always an h1.
- **Patterns:** Card (clickable cards use the stretched-link pattern: a `CardLink` in the title covers the card, is named by the title only, and the card draws the focus ring; wrap other buttons and links in `CardAction` to keep them above the overlay. Card itself takes no `to`/`href`/`target`/`rel`. Known tradeoff: the overlay sits over the card body, so text in a clickable card can't be selected with the mouse), StatCard (one sr-only summary, visual parts aria-hidden), Tabs and NumberedTabs (Base UI Tabs), Accordion (Base UI, h3 titles by default; `value` takes a value, an array or null for all closed, and `onValueChange` always gets an array), Breadcrumbs, Pagination (`getPaginationRange` for the page list), EmptyState, Alert (`status` role for info and success, `alert` for warning and error) and Banner (always `status`), PageHeader, SectionHeader, Reveal, CountUp, MediaFrame and CheckList.
- **Overlays:** Dialog and Sheet share `patterns/Dialog/OverlayShell.jsx` (Base UI Dialog: focus trap, scroll lock, focus return, outside content inert). Both take `trigger`, `title` (required, dev warning), `description`, `children`, `footer` and `dismissible`; close from the footer with `DialogClose` or `SheetClose` around a Button. DropdownMenu (Base UI Menu, item highlight matches Select) and Popover (Base UI Popover) take `trigger`, `side` and `align`; their props go to the trigger and `popupClassName` to the popup. Layers, lowest to highest: backdrop `z-(--ds-z-overlay)` 300, dialogs `-modal` 400, menus and selects `-dropdown` 500 (so they open above a dialog), popovers `-popover` 550, tooltips `-tooltip` 600, toasts `-toast` 700. `tokens/zOrder.test.js` guards the order. Tooltip descriptions inside a dialog stay readable: Base UI marks body children outside the dialog aria-hidden, but aria-describedby still reads content it points at directly.
- **Toast:** mount `<Toaster />` once; call `toast.success/error/info/warning/promise` (sonner) or `useToast()`, which has the old `components/ui/Toast.jsx` method names. Sonner reads its colors from CSS variables, which Toaster sets inline from role tokens. Toasts shown while a modal Dialog or Sheet is open sit outside the modal's focus scope, so keyboard users can't tab to them; they auto-dismiss, and the close button still works with a pointer (checked in Chromium). Don't put the only copy of an action in a toast.
- **Forms:** FormField wires a label, hint and error to one control (cloned, or a render function), with `layout="inline"` for Checkbox and Switch and `group` for RadioGroup. SearchInput debounces `onSearch`, clears through a real input event so controlled inputs stay in sync, searches with the text the field shows when the debounce fires (so a parent that trims or lowercases still gets `onSearch`), drops a pending search when the value changes from outside, and is named by `label` (visually hidden), `aria-label`, `aria-labelledby` or a FormField (through `FormFieldContext`; the SearchInput must be FormField's direct child to pick up the label); otherwise it falls back to "Search" with a dev warning. FormField warns when its child also gets a `label` prop. FilterBar renders select, chip and custom filters from config (each with a `key`) and resets them with one `onClear({ [key]: emptyValue })` call (filters without a `key` are left out), so apply the reset in one setState; without `onClear` the Clear filters button stays hidden and dev warns; its controls are md (48px) by default, `size="sm"` is the dense desktop opt-in, and chips stay 40px with an `after:` hit area.
- **Tables:** `Table` and its parts (`TableCaption`, `TableHeader`, `TableBody`, `TableRow`, `TableHead`, `TableCell`) are semantic markup for simple tables: header cells use `scope="col"`, `density` is comfortable (default) or compact, and a table wider than its container sits in a focusable `role="region"` named by its caption. `DataTable` builds on it for admin lists: `columns` config (`cell`, `sortable`, `align`, `width`, `hideBelow`; keep the array stable so client sorting stays memoized), client or `manualSorting`, one `pagination` prop (`{ pageSize, page, defaultPage, onPageChange, manual, rowCount }`; manual pages derive pageCount from rowCount, a page past the end is written back once, but not while loading or before a manual `rowCount` is known, so a deep-linked page survives the first fetch), `loading` with aria-busy (skeleton rows when there are no rows yet, the old rows dimmed during a page change), a default "No results" EmptyState, `selectable` with a page-wide indeterminate select-all, `rowActions` in a labelled kebab DropdownMenu, a `toolbar` slot and `rowHref` / `onRowClick`. A clickable row has a real link (or button) in its first cell that wraps the cell's visible text (an sr-only row name is added only when the cell has no text), and the `<tr>` forwards other clicks to it unless they land on a control or end a text selection (no overlay, no `position: relative` on the row). Ctrl, meta and shift clicks and middle clicks on a linked row open the link in a new tab through `window.open(href, '_blank', 'noopener')`, which keeps the Referer like a native ctrl-click (an untrusted click carrying modifiers isn't honored the same way in every browser); `onRowClick(row, event)` gets the original event. A new sort goes back to page 1. Selection is kept by id across filtering, so bulk actions can include rows the current filters hide; clear or intersect it when filters change if that matters. Below md (`useMediaQuery` from `hooks/`) rows stack as labelled cards (no `hideBelow` columns, a "Sort by" select when columns sort) unless `mobileLayout="scroll"`; tests render that layout with `mockViewport(375)` from `test/browserMocks.js`.
- **Organisms:** `organisms/<domain>/<Component>/` (app-shell, site), one barrel per domain plus `organisms/index.js` (the barrel test checks both and that organisms never import app `components/`, `context/` or `pages/`). Organisms compose primitives and patterns and take their data as props; they never fetch. Plain `.js` modules (nav config, shared links) may sit in a domain folder, but a component file there fails `npm run check:stories`. App shell: `AppShell` (sidebar 280px at 1280px and up, 80px rail from 1024 to 1279px with an expand toggle saved under `mv.sidebar.collapsed`, a left Sheet below 1024px that opens on the active nav link), `AppSidebar`, `AppTopBar`, `SidebarNavItem`, and `nav.js` (`MEMBER_NAV`, `ADMIN_NAV`, `findActiveItem`, `buildUserMenuItems`; `nav.test.js` fails when an App.jsx route under /dashboard or /admin has no nav item). Site: `SiteHeader`, `SiteFooter`, `CTABand`, pixel-matched to the old public layout parts; they use the site breakpoints `max-site-sm:` (480), `max-site-md:` (992) and `max-site-lg:` (1200).
- **Charts:** `ChartCard` holds one config (`data`, `xKey`, `series` [{ key, label, color 1 to 6 }], `valueFormatter`, `xFormatter`) that feeds both the chart inside it (a bare `<BarChart />` or `<LineChart />`) and its "View as table" Table (a pressed toggle with aria-pressed; `tableView={false}` leaves it out), so the numbers always match. Charts take colors and sizes from `tokens/tokens.js` (`chartColors`, `tokens`), never hex, render our own legend markup, turn animation off with `useReducedMotion()`, and use recharts' keyboard layer (arrow keys move the highlighted bar and tooltip). In jsdom call `mockResizeObserver()` so ResponsiveContainer gets a size, and test structure and attributes rather than SVG geometry.

## Token classes

| Kind | Classes |
|---|---|
| Color | `bg-surface-*` (including `bg-surface-inverse` for dark tooltips), `text-text-*`, `border-border-*`, `bg-status-*` and `-subtle`, `text-status-*`, `*-chart-*` |
| Spacing | `p-ds-*`, `m-ds-*`, `gap-ds-*` (`none`, `xxs`, `xs`, `sm`, `md`, `lg`, `xl`, `xxl`, `section`) |
| Radius | `rounded-tag`, `-input`, `-control`, `-card`, `-sheet`, `-panel`, `-chip` (4, 8, 12, 16, 24, 32, pill) |
| Type | `text-caption`, `-body-sm`, `-body`, `-lead`, `-h4`, `-h3`, `-h2`, `-h1`, `-display` (sizes with line heights) |
| Shadow | `shadow-card`, `-card-hover`, `-float`, `-overlay`, `-button-brand` |
| Easing | `ease-enter`, `ease-exit`, `ease-move` |

Role variables such as `--text-primary` live in `:root`, not in Tailwind's font-size namespace (`--text-*` in `@theme`). Tailwind sees them through `--color-text-primary`, so the class is `text-text-primary`. `text-body` is a font size, `text-text-primary` is a color.

Tier 1 primitives (`var(--mv-...)`) never appear outside `tokens/`; CSS in `styles/` uses role variables (`--border-brand-subtle`, `--ds-duration-*`), and the drift test fails otherwise. Tokens come from `tokens/tokens.json`. Run `npm run tokens` after editing it. It writes `tokens/tokens.css`, `tokens/tokens.js` and `lib/twMergeConfig.js` (the theme scales `cn()` needs, built from every `@theme inline` key). Don't edit those files by hand: the drift test fails when any of them is stale.
